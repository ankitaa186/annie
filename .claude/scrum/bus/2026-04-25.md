### Three smoking guns (root cause of the $88 gap)

**1. completion_tokens is the chunk count, not the token count.** `backend/api/providers/gemini_provider.py:641` increments `token_count += 1` once per streamed chunk, then line 686 substitutes `completion_tokens = token_count`. Output token undercount factor is ~50x. Same pattern appears at line 1037 (the function-call branch). Also: ChatGPT provider's path at `chatgpt_provider.py:543` is `usage.get("completion_tokens", token_count)` — falls back to chunk count when OpenAI's streaming response doesn't include `usage` (which it won't unless `stream_options.include_usage=true` is set; couldn't verify quickly but the today-trace example showed `promptTokens: 0`, suggesting the same shape problem is happening for ChatGPT cost too).

These aren't real conversational turns — they look like a code path that records a placeholder before the actual `count_tokens()` succeeds, OR a retry/error path that ships `prompt_tokens=0` then hits the "tracking with token_count > 0" branch at line 1034 where `prompt_tokens = 0` initially and the count_tokens call silently fails into the `except: pass`.
