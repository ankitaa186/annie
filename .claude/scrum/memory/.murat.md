### Provider mock patterns (Story 23.1 — useful for any future provider work)

### Story 24.1 lessons (google.genai migration)
- **Live Gemini API tests**: gate behind `RUN_LIVE_E2E=1` env var via `@pytest.mark.skipif(not os.getenv("RUN_LIVE_E2E"), ...)`. Default `make test` / CI runs skip; manual opt-in only. ~$0.01-$0.05 per run on gemini-3.1-pro-preview for a one-tool one-response cycle.
- **conftest GOOGLE_API_KEY override gotcha**: `tests/conftest.py:91-95` `mock_env_vars` is autouse — it clobbers `GOOGLE_API_KEY` to `test-google-key-12345` for every test. Live tests must recover the real key from `/proc/1/environ` (the original docker-compose-injected env, untouched by conftest). Use `monkeypatch.setenv("GOOGLE_API_KEY", real_key)` to restore, then construct provider. `get_config()` is uncached, so re-construction picks up the patched value.
- **SDK 1.73.1 thought_signature wire shape**: Real Gemini 3.x deliveries put `thought_signature` (Optional[bytes]) directly on the same `types.Part` that carries `function_call`. Capture per-Part in the streaming loop iteration (`gemini_provider.py:867-910` pattern). Pre-1.40 SDK had `extra='forbid'` on Part with no signature field → `_remove_extra_fields` silently stripped the value before Pydantic. Lesson: whenever a provider returns Pydantic-validated objects, the `extra='forbid'` setting is a hidden cliff — always check the SDK changelog for new fields when bumping versions.
- **Live signature observation**: structured log line `"Gemini requesting tool: <name>" extra={tool_name=..., has_thought_signature=true, thought_signature_bytes=N}` — use this in Loki for monitoring. Real signatures observed during my smoke run ranged 470-959 bytes per turn.
- **Mocking thought_signature in tests**: extend `_Part` and `_Candidate` test fakes with `thought_signature: Optional[bytes] = None` parameter. For multi-part candidates (parallel function_calls), introduce a separate `_MultiPartCandidate` class — the default `_Candidate` collapses to a single Part.
- **Production flow shape (verified end-to-end 2026-04-25)**: POST /api/chat returns `{conversation_id, status:"streaming", stream_url}`. GET /api/stream/{id} delivers SSE events. Use `requests.get(stream=True).iter_lines()` for clean consumption — `urllib.request` chunked-reading hangs on long streams. Event types: `status`, `token`, `tool_call_started`, `tool_call_completed`, `done`, `error`.

### Story 24.1 cost-math defect (flagged for Ankit / Story 24.2)
- `backend/api/observability/cost.py:94-160` `calculate_gemini_cost` double-bills cached tokens. Bug: `total_cost = input_cost + output_cost + cached_cost` where `input_cost` is computed on FULL `prompt_tokens` (which already includes cached). AC15's +30d watchdog ("≥40% input cost reduction") will not land without fixing this. Recommend: subtract cached portion from input_cost before adding cached_cost. Add a real cost-reduction unit test (not just "field is present").

### Bug 25.2 lessons (Gemini cost-math fix — cached double-count)
- **Langfuse REST observation shape**: `usageDetails` exposes ONLY `{input, output, total}` to API consumers — there is NO `cached_input` / `input_cached` field returned even though Annie emits it via the SDK. The cached signal is encoded into `costDetails.total` as a residual: `cached_cost = costDetails.total - costDetails.input - costDetails.output`, which decodes to integer-token counts at $0.20/M (gemini-3.1-pro-preview ≤200K rate). Use this for any future cache-recon tooling — don't trust the absence of `input_cached` in the API response as evidence the plumbing is missing.
- **37-trace re-audit script** at `/tmp/bug_25_2_decode.py` (also kept on backend container at `/tmp/bug_25_2_decode.py`). Pattern: page `GET /api/public/observations?type=GENERATION&fromStartTime=…&toStartTime=…`, filter by model substring `gemini-3`, decode cached residual, compute pre-fix vs post-fix cost. Cost: $0 (Langfuse REST is free for observation reads).
- **Per-cache-hit overstatement varies 1.7x – 6.5x**, NOT a flat "5.5x". Ratio depends on cache density: high-cache + tiny-output = ~6.5x (e.g. 605e1982: cached=20255 of 21723 prompt + only 26 output → 6.55x). Low-cache or big-output = ~1.7x. Aggregate overstatement across 39 traces in 24h window: **1.515x** (33.98% reduction projected post-fix).
- **AC7 watchdog threshold recalibration**: 24.1's +30d ≥40% input-cost-reduction watchdog was calibrated against the over-stated baseline. Post-25.2, the baseline shrinks ~34%, so the cache-discount-from-here onwards is what matters. Real cache discount on the cached-portion only is ~90% (full $2/M → cached $0.20/M = 90% off). Across a typical conversation, cached fraction averages ~0.7 by turn 2+. So expected post-fix input-cost reduction vs a no-cache baseline is ~63%. **Suggested revised threshold: ≥50%** (not 40%) because: (a) the over-statement was masking how aggressive the cache discount really is, (b) gemini-3 implicit caching is firing on most multi-turn convos, (c) 50% leaves headroom below the 63% theoretical max for noise. If the watchdog fires under 50%, that's a real problem worth investigating.
- **AC4 e2e ±2% recon runbook** (post-push, ~24h after merge):
  1. Pull 5+ post-fix cache-hit traces: same Langfuse query as the audit script, filter for traces with `costDetails.total - costDetails.input - costDetails.output > 0.0001` (positive cached residual) and `startTime >` push-time + 1h.
  2. For each, recompute expected cost = `(prompt - cached) × $2/M + cached × $0.20/M + output × $12/M` where cached = round(residual / $0.20/M).
  3. Compare to AI Studio billing: in Google Cloud Console → Billing → Reports → filter by "Generative Language API" service + filter to the hour the trace landed → divide by token volume to get unit cost, then multiply by tokens. Or, for one-off: AI Studio dashboard for project → API metrics tab.
  4. Tolerance gate: `abs(expected - AI_Studio_billed) / AI_Studio_billed ≤ 2%`. If 5/5 within ±2%, AC4 passes. If 1+ outside, capture trace IDs, re-check rates against Google's published table, escalate.
- **Mock fidelity bar set in `test_bug_25_2_cost_math.py`**: SDK-agnostic doubles (`_UsageMetadata`, `_FinishReason`, `_Part`, `_Content`, `_Candidate`, `_Chunk`) — zero `google.genai` imports. `MagicMock(spec=[...])` for genuine field-absence (vs Mock-fabricated). `_AsyncChunkIter` correctly models async iteration. Pattern is reusable for any future Gemini provider work.
