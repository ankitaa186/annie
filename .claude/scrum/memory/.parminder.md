# Parminder's Project Understanding (Architect)
Last Updated: 2026-04-16 10:00

## Project Overview
Annie is a microservices system: Telegram Bot -> Backend API (FastAPI) -> MCP Server -> External Services, with Redis for state, agentic-memories for long-term storage, and Langfuse for observability.

## Architecture Assessment

### Current Architecture (Healthy)
- **Backend**: FastAPI with well-structured modules (routes, providers, models, middleware, observability)
- **LLM Layer**: Provider abstraction (base.py) with grok, chatgpt, gemini providers - good pattern
- **MCP Server**: HTTP transport with FastAPI, 14+ tools in modular registry pattern
- **State**: Redis for sessions, profiles, rate limiting, memory queues
- **Proactive AI**: Full module with activity tracking, evaluators, triggers, gate pattern
- **Observability**: Langfuse tracing with @observe decorators, cost tracking

### Architecture Strengths
- Clean provider abstraction for LLMs
- MCP tool registry pattern is extensible
- Proactive AI system is well-isolated
- File handling with process-and-discard (no persistence) is secure
- Middleware layer (Cloudflare auth, rate limiter) is production-ready

### Architecture Concerns
- No systematic test coverage (Epic 6 not done)
- PROJECT_STATUS.md is severely outdated (says "Not Started" but most things are done)
- Browser service adds complexity (Patchright + VNC sidecar)
- Multiple LLM providers increase surface area for failures
- No circuit breaker pattern documented for external service calls (though memory has one)

### Tech Debt
- Timeout configuration story (2.7) exists but unclear if fully resolved
- PROJECT_STATUS.md needs complete rewrite
- Docker compose likely has grown complex with all these services

### Key Directories
- `backend/api/providers/` - LLM provider implementations
- `backend/api/proactive/` - Proactive AI system
- `backend/api/routes/` - API endpoints
- `mcp_server/tools/` - All MCP tool implementations
- `telegram_bot/` - Bot with file handling, media sending
- `web/` - React/Vite web UI (partial)
- `browser/` - Browser automation

## Architecture Decisions Log
- MCP communication: Docker exec -> HTTP transport (migrated)
- LLM: Multi-provider with fallback (Grok primary, ChatGPT fallback, Gemini for multimodal)
- Memory: agentic-memories with Redis fallback queue and circuit breaker
- Observability: Langfuse (not custom)
- Web UI: React + Vite + Tailwind
